# PrimaryPlayButton — composant dédié (2026-08-06)

Mission ciblée : Camille a donné un cahier des charges CSS très précis
(géométrie, dégradé, contour, relief, highlight, texte, icône, états
normal/pressed/hover/focus/disabled) pour le bouton JOUER, avec une
méthode obligatoire : construire et vérifier le composant ISOLÉ sur fond
neutre avant réintégration dans le lobby.

## Process suivi

1. Composant construit dans `public/dev-play-button.html` (4 états
   affichés côte à côte sur fond gris neutre).
2. Comparaison directe par crop : capture isolée vs crop du bouton JOUER
   de la planche, redimensionnés à la même hauteur, empilés.
3. Écarts trouvés et corrigés :
   - Texte trop petit/pâle (grand vide autour, contour bleu fin) → agrandi
     nettement (clamp jusqu'à 46px), contour quasi noir épaissi (2px),
     ombre portée ajoutée pour le relief.
   - **Bug trouvé en cours de route** : le sélecteur générique `.row span`
     du harnais (légendes d'état) avait une spécificité CSS PLUS FORTE que
     `.play-btn__label` et écrasait silencieusement le texte du bouton à
     12px — invisible en lisant le CSS, trouvé par calcul (`getComputedStyle`
     ≠ valeur déclarée). Corrigé (classe dédiée `.row-caption`).
   - Icône plate → dégradé 2 tons (highlight clair) + contour sombre,
     agrandie.
   - Largeur/hauteur réelles sous la cible de Camille (261×76px mesurés vs
     290-320×82-94px demandés) → coefficients `dvw`/`dvh` recalibrés.
4. Réintégré dans `spike3d-menu.html` (`#play-btn`) : composant autonome,
   plus aucun recours à `.el-btn`. Positionné par marges droite/basse
   (pas le système left/top en % des autres zones — Camille a donné des
   marges explicites pour ce composant précis).

## Vérification

- Dimensions réelles sur les 5 résolutions imposées : toutes dans la
  fourchette demandée (290-320 × 82-94px), aucun écran ne tombe hors
  cible.
- Aucun chevauchement avec la carte de mode (vérifié par calcul,
  `getBoundingClientRect`).
- 5/5 PASS zéro-scroll, 0 erreur console.
- `dvw`/`dvh` utilisés au lieu des `vw`/`vh` suggérés en exemple par
  Camille — cohérent avec le correctif déjà appliqué projet-wide (bug
  viewport mobile réel diagnostiqué plus tôt sur cet écran).
