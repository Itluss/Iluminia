# Fiche d'itération — Système d'inventaire (icône + fenêtre modale)

## Objectif utilisateur
Ajouter un inventaire consultable : une icône sous le panneau Quête
(haut-gauche), effet de survol, ouverture d'une fenêtre modale centrale au
clic.

## Décisions validées par Camille (questions posées avant implémentation)
- **Contenu** : uniquement les ressources RÉELLEMENT suivies par le jeu
  aujourd'hui — pièces (`progress.coins`), étoiles (`progress.stars`),
  fragments de pont actuellement en main (`heldPieces` : 1/4, 1/2, 3/4). Pas
  d'objets RPG fictifs (épée/armure/rareté) : la planche
  `public/ui/interface.png` (section 3) sert de référence de STYLE
  uniquement (en-tête vert arrondi, slots carrés, bouton fermeture rond),
  pas de contenu à copier.
- **Position** : icône collée sous `#quest-box` (extension du bloc
  Tutoriel+Quête en haut-gauche), pas une icône isolée au milieu de l'écran.

## Fichier concerné
`public/spike3d-village.html` uniquement (HUD DOM + petite logique JS de
lecture d'état existant — aucune nouvelle donnée de jeu créée).

## Changements
1. Nouveau bouton `#btn-inventory` (icône `icon-pouch.png`, déjà utilisée
   pour les fragments de pont — réemploi, pas de nouvel asset) positionné
   dynamiquement sous `#quest-box` (recalcul à chaque changement de texte de
   quête + resize, même mécanique que `positionQuestBox`).
2. Survol : même langage visuel que le hover doré déjà établi sur
   `#action-bar` (halo `#ffdca0` + léger soulèvement) — cohérence du système
   d'interaction du HUD.
3. Clic : ouvre `#inventory-overlay` (fond assombri, pattern déjà utilisé par
   `#end`/`#pause-overlay`) contenant `#inventory-modal` : en-tête vert
   (`var(--el-green)`) avec titre + bouton fermeture rond, corps
   crème/tan avec les slots : Pièces, Étoiles, Fragments ¼/½/¾ (valeurs
   lues en direct depuis `progress.coins`, `progress.stars`, `heldPieces`).
4. Fermeture : bouton ✕, ou clic sur le fond assombri en dehors de la carte.

## Hors périmètre (ne pas toucher)
- Aucun onglet Équipement/Consommables/Ressources/Quêtes/Autres (pas de
  contenu correspondant dans le jeu).
- Aucune icône/objet RPG fictif (épée, armure, anneau, rareté).
- Aucun changement de gameplay/caméra/`spike3d-planet2.html`.
- Aucune régression sur les panneaux existants (quête, XP, ressources,
  pièces de pont, barre d'action).

## Critères d'acceptation
- Icône visible sous le panneau Quête, bien collée (pas de chevauchement).
- Survol : effet doré cohérent avec le reste du HUD (pas de nouvel style
  disparate).
- Clic : modale centrée, lisible, affichant les valeurs réelles actuelles
  (pièces/étoiles/fragments), fermeture fonctionnelle (✕ et clic extérieur).
- Aucune régression HUD.

## Cycle de correction n°1 (revue initiale : 3 défauts majeurs)
1. Slots fragments (¼/½/¾) sans icône (texte seul) → ajout d'une pastille
   ronde peinte procédurale (dégradé bois/cuivré, bordure brune), même
   gabarit que les icônes Pièces/Étoiles. Pas de nouvel asset PNG généré.
2. Grille 4+1 asymétrique → largeur de la modale réduite à `min(320px,86vw)`
   pour forcer le retour à la ligne après 3 slots (flex-wrap +
   justify-content:center centre chaque ligne) → 3+2 centré.
3. Fond assombri jugé insuffisant → opacité `#inventory-overlay` 0.45→0.55.
   Vérifié après coup par mesure de pixel directe (script Playwright
   ponctuel, supprimé après usage) : RGB(135,118,85) sans overlay →
   RGB(72,67,49) avec overlay au même point (1400,700) — assombrissement
   d'environ 47%, cohérent avec le calcul attendu. La 2e revue du
   sous-agent jugeait encore l'effet « non perceptible » : mesure
   objective contredisant cette lecture subjective — aucune action
   supplémentaire (budget d'un seul cycle de correction déjà consommé).

Recadrage écarté (vérifié faux) : la revue initiale signalait aussi une
icône de header différente de celle du bouton d'ouverture — les deux
utilisent le même fichier `/ui/icons/icon-pouch.png` (vérifié dans le code),
pas de correction nécessaire.

## Itération n°2 — retour Camille : icône trop petite, peu évocatrice, menu pas beau
Retour direct de Camille : « l'icône à gauche est trop petite », « l'image de
l'icône n'est pas claire et évocatrice », « le menu qui s'ouvre n'est pas
beau », « je préfère largement la planche ». Contrairement à l'itération 1,
la STYLE de la planche est maintenant explicitement demandée comme cible de
qualité (pas seulement une référence lointaine) — le contenu reste limité
aux ressources réelles (décision inchangée), mais la finition doit s'en
rapprocher nettement.

Changements :
1. Besoin explicite identifié (icône peu lisible) → génération d'un nouvel
   asset via le pipeline documenté dans `asset-rules.md`
   (`node scripts/generate-image.mjs`, référence de style par défaut =
   `public/ui/interface.png`) : `public/ui/generated/icon-backpack.png`, un
   sac à dos peint (silhouette claire, contour épais, palette bonbon/brun-
   cuir + accent vert) remplaçant l'ancienne pochette (`icon-pouch.png`),
   jugée ambiguë (déjà relevé par le reviewer à l'itération précédente : lu
   comme une fiole). `icon-pouch.png` reste utilisé tel quel pour
   `#pieces-panel` (fragments de pont en main pendant le mini-jeu du pont —
   fonctionnalité différente, non concernée par ce retour).
2. `#btn-inventory` agrandi (clamp 40-54px → clamp 50-68px), glyphe interne
   60%→72% de la boîte.
3. Modale redessinée : en-tête vert en dégradé + liseré `--el-green-dark`
   (plus de profondeur), carte élargie à `min(580px,90vw)` pour accueillir
   les 5 slots sur UNE SEULE rangée (plus de grille 3+2), slots agrandis
   (82px→94px, icônes 30px→38px), double bordure (brune + liseré clair
   interne) et ombre portée pour un rendu plus « fini ».
