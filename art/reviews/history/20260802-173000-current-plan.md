# Fiche d'itération — info-bulle nom des personnages au survol

## Objectif utilisateur
Camille ne sait pas identifier qui est Elda dans la scène. Ajouter une
info-bulle (style jeu, pas un tooltip HTML natif) qui affiche le nom du
personnage survolé à la souris.

## Fichier concerné
`public/spike3d-village.html` uniquement. Vérifié : `spike3d-planet2.html`
ne contient aucun PNJ nommé (uniquement le héros) — non concerné.

## État actuel (lu dans le code)
- Système de survol déjà en place : `hoverTargets()` (l.2091) renvoie les
  hitboxes invisibles d'Elda/du présentoir de leçon/Bram/Nima + les planches
  à ramasser ; `pointermove` (l.2283) raycaste dessus, change le curseur en
  `pointer` et appelle `setHoveredGroup()` (halo lumineux via
  `userData.glowMeshes`).
- Chaque hitbox porte déjà `userData.haloTarget` (le groupe à faire briller)
  mais aucune information de nom.
- Noms déjà utilisés ailleurs dans le code (dialogues) : `'Elda'`, `'Bram'`,
  `'Nima'` — à réutiliser tels quels pour la cohérence.

## Changements prévus
1. Ajouter `userData.name` sur les 3 hitboxes de PNJ nommés
   (`eldaHitbox`/`bramHitbox`/`nimaHitbox`) — PAS sur `lessonHitbox`
   (présentoir, pas un personnage) ni sur les planches à ramasser (déjà
   étiquetées en 3D par leur fraction).
2. Nouvel élément HUD `#name-tooltip` : pastille sombre discrète (même
   famille visuelle que `#interact-hint`), positionnée près du curseur,
   affichant le nom, `pointer-events:none` (ne doit jamais intercepter de
   clic), clampée pour ne jamais déborder de l'écran.
3. Dans le handler `pointermove` existant : si la cible survolée porte un
   nom, positionner + afficher la pastille ; sinon la masquer. Ajouter un
   `pointerleave` sur le canvas pour la masquer si la souris quitte la zone
   de jeu.

## Hors périmètre
- `spike3d-planet2.html` (aucun PNJ nommé).
- Tout changement au système de halo/curseur existant au-delà de l'ajout du
  nom (comportement de glow inchangé).
- Toute info-bulle pour les objets non-personnages (planches, présentoir de
  leçon, portail).

## Risque identifié (leçon du cycle précédent)
Un chevauchement HUD (panneau recouvert par la barre d'action) est passé
inaperçu lors de la dernière itération malgré une vérification DOM correcte
— seule une capture réelle l'a révélé. Vérifier explicitement par capture
que la pastille ne chevauche/déborde aucun autre élément HUD (HUD texte,
quest-box, barre d'action) à plusieurs positions de curseur.

## Critères d'acceptation
- Survoler Elda/Bram/Nima affiche leur nom près du curseur, dans un style
  cohérent avec le HUD existant.
- La pastille disparaît proprement hors survol / à la sortie du canvas.
- Aucune régression sur le curseur/halo existant, le dialogue, le
  déplacement, le ramassage de planches.
- Aucun débordement d'écran ni chevauchement HUD sur la capture finale.
