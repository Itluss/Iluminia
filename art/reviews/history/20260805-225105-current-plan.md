# Plan — Phases 2+3 : branchement du design system sur les écrans réels (2026-08-05)

Suite de la Phase 1 (fondation, `public/ui/theme.css` + `icons.js` +
`ui-styleguide.html`, validée). Camille a demandé d'enchaîner toutes les
phases sans repasser par une validation intermédiaire. Ce lot couvre les
Phases 2 (composants gameplay) et 3 (écrans/fenêtres) ensemble, sur
`spike3d-menu.html` et `spike3d-arena.html`.

## Changements

**Les deux fichiers** : `<link rel="stylesheet" href="ui/theme.css">` +
`<script src="ui/icons.js">` ajoutés. Tous les boutons peints en PNG (lots
5-6, `btn-primary-fp.png` etc.) supprimés et remplacés par les classes
`.el-btn` (CSS pur, plus aucune image). Toutes les couleurs `var(--el-brown/
cream/tan/green*)` (ancienne palette parchemin) remplacées par les tokens du
design system (`var(--el-gold/cyan/success/...)`).

**spike3d-menu.html** : fond CSS pur (dégradés radiaux + étoiles, remplace
`menu-bg-texture-v3.png`), bouton Jouer/Collection en `.el-btn`, badges
cadeaux/avatar/familier en `.el-btn--icon.el-btn--circle` (couleurs
différenciées : or/neutre/cyan), les 4 fenêtres (cadeaux/garde-robe/
familiers/collection) en `.el-modal-card`, icônes SVG du sprite à la place
des emojis (🎁→gift, 🥚→egg, 🐾→paw, ▶→play).

**spike3d-arena.html** : joystick, boutons de compétence pets (`.pet-btn`,
anneau de charge migré de `background` inline en JS vers la custom property
CSS `--charge`), bandeau de question, barre d'énergie, classement flottant,
carte pré-partie/fin de manche/quiz, tous retheme sur les tokens. Boutons
Jouer/Rejouer/Collection/Accueil/Continuer en `.el-btn`.

## Bug de capture (pas un bug de code)

Première capture de l'écran de fin de manche montrait l'overlay pré-partie
ET l'écran de fin de manche superposés — dû au script de test qui appelait
`simulateMatchEnd()` sans avoir cliqué "Jouer" d'abord (`#start-overlay`
n'est masqué qu'au clic réel). Recapturé avec le clic — comportement normal.
