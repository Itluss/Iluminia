# Fiche d'itération — Menu inventaire : diagnostic et correction (pas une refonte)

## Objectif utilisateur
Camille jugeait la version actuelle du menu inventaire (`#inventory-modal`,
`public/spike3d-village.html`) « nulle » et demandait une recréation
complète pour coller à `art/board/image.png` (section 3, « MENU
INVENTAIRE »), suivie d'une comparaison automatique via l'API GPT (vision)
pour obtenir des indications de correction.

## Constat après inspection (avant de recréer quoi que ce soit)
Le code utilisait déjà l'approche la plus fidèle possible : un fond
d'image généré (`public/ui/generated/inventory-panel-banana.png`, calqué
sur la planche) qui porte header/onglets/grille peints, avec seulement les
éléments réellement dynamiques positionnés par-dessus en CSS (bouton
fermer, 2 cases cliquables pièces/étoiles, panneau de détail, pied de
page). Cette approche n'était PAS le problème — 3 bugs concrets faisaient
paraître le panneau bien pire qu'il ne l'est :
1. `scripts/capture-inventory.mjs` prenait la capture avant la fin de
   l'animation CSS de pop-in (.35s), figeant le panneau à ~55% de sa taille
   finale sur CHAQUE capture/revue précédente — fausse impression de
   panneau minuscule/cassé.
2. `.inv-footer` n'avait pas `box-sizing: border-box` : `width:100% +
   padding 5.5%` poussait les compteurs pièces/étoiles ~11% hors du cadre
   du panneau, rendus invisibles par `overflow:hidden`.
3. `public/ui/icons/res-coin.png` (icône pièce) avait un halo opaque
   brunâtre autour du cercle doré — même défaut que les icônes rejetées
   précédemment (voir mémoire feedback-decoupe-colorkey-echoue), mais issu
   cette fois d'une génération IA, pas d'un color-key.

## Décision (validée par Camille via question de clarification)
Pas de recréation complète du panneau : correction ciblée des 3 bugs +
comparaison GPT vision planche/capture pour vérifier la fidélité restante.
Pour les icônes qui nécessitaient une régénération (pièce), méthode choisie
par Camille : génération IA (gpt-image-1), pas de color-key.

## Changements appliqués
- `scripts/capture-inventory.mjs` : neutralise l'animation CSS du modal
  avant la capture (`animation: none !important`) pour une capture
  déterministe à taille finale.
- `public/spike3d-village.html` : `.inv-footer` → `box-sizing: border-box`
  (corrige le débordement) ; ajout de `.inv-slot.selected` (état de
  sélection visuellement absent jusqu'ici) ; icônes du pied de page
  agrandies (`clamp(18px,2.2vmin,24px)` → `clamp(22px,2.7vmin,30px)`,
  suite à l'indication GPT vision « icônes trop petites »).
- `public/ui/icons/res-coin.png` : régénérée (gpt-image-1, sans référence
  de style pour éviter d'hériter le halo de la bible graphique), fond
  réellement transparent vérifié pixel par pixel (canvas Playwright, alpha
  = 0 hors silhouette).
- `scripts/compare-inventory.mjs` (nouveau) : appelle l'API OpenAI
  (gpt-4o vision) pour comparer `art/reviews/latest.png` à
  `art/board/image.png` et écrire des indications de correction dans
  `art/reviews/gpt-comparison.md`.
- `art/generated/manifest.json` : entrée ajoutée pour `res-coin.png`.
